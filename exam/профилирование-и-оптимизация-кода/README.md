# Профилирование и оптимизация кода

Материалы для экзамена по теме "Профилирование и оптимизация кода".

## Структура файлов

- **задания.md** - Описания заданий в формате Markdown
- **ответы.md** - Ответы и объяснения оптимизаций в формате Markdown
- **задания.py** - Python файл с неоптимизированным кодом для практики
- **ответы.py** - Python файл с оптимизированными решениями
- **теория-сложности-алгоритмов.md** - Теоретический материал о сложности алгоритмов

## Использование

### Для изучения теории
1. Прочитайте `теория-сложности-алгоритмов.md` для понимания основ
2. Изучите задания в `задания.md`
3. Попробуйте решить задания самостоятельно, используя `задания.py`

### Для практики
1. Откройте `задания.py` в редакторе
2. Запустите функцию с заданием:
   ```python
   from задания import задание_1_неэффективный_поиск
   задание_1_неэффективный_поиск()
   ```
3. Профилируйте код, найдите узкое место
4. Оптимизируйте код
5. Сравните с решением в `ответы.py`

### Для проверки решений
1. Откройте `ответы.py`
2. Запустите соответствующую функцию с ответом:
   ```python
   from ответы import ответ_1_неэффективный_поиск
   ответ_1_неэффективный_поиск()
   ```
3. Сравните производительность с исходным кодом

## Инструменты для профилирования

### Измерение времени выполнения
```python
import time

start = time.perf_counter()
# ваш код
end = time.perf_counter()
print(f"Время выполнения: {end - start:.4f} секунд")
```

### Профилирование памяти
```python
import tracemalloc

tracemalloc.start()
# ваш код
current, peak = tracemalloc.get_traced_memory()
tracemalloc.stop()
print(f"Пиковое использование памяти: {peak / 1024 / 1024:.2f} MB")
```

### cProfile для детального анализа
```python
import cProfile
import pstats

profiler = cProfile.Profile()
profiler.enable()
# ваш код
profiler.disable()
stats = pstats.Stats(profiler)
stats.sort_stats('cumulative')
stats.print_stats(10)
```

## Критерии оценки

При проверке решений обращайте внимание на:

1. **Правильность оптимизации** - Код должен работать корректно
2. **Улучшение сложности** - Должно быть видимое улучшение O-нотации
3. **Практическая эффективность** - Код должен работать быстрее на реальных данных
4. **Читаемость кода** - Оптимизация не должна ухудшать читаемость
5. **Понимание проблемы** - Экзаменуемый должен объяснить, в чем была проблема
