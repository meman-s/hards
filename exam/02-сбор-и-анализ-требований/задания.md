# Задания: Сбор и анализ требований

## Задание 1: Типы требований

Для системы электронной коммерции определите и опишите:
1. 3 бизнес-требования
2. 5 пользовательских требований
3. 10 функциональных требований
4. 5 системных требований
5. 8 нефункциональных требований (минимум по 2 из каждой категории)

## Задание 2: CRUD-анализ

Проведите CRUD-анализ для системы управления проектами со следующими ролями:
- Менеджер проекта
- Разработчик
- Тестировщик
- Заказчик

Определите права доступа для каждой роли к сущностям: Проект, Задача, Комментарий, Файл.

## Задание 3: MoSCoW приоритизация

Для системы управления библиотекой приоритизируйте следующие требования по методу MoSCoW:
- Поиск книг по названию
- Резервирование книги онлайн
- Уведомления о возврате книг
- Рекомендательная система
- Интеграция с внешними библиотеками
- Мобильное приложение
- Система рейтингов и отзывов
- История выдачи книг

## Задание 4: Пользовательские истории

Напишите 5 пользовательских историй для системы заказа еды, соблюдая критерии INVEST:
- Независимость (Independent)
- Переговоры (Negotiable)
- Ценность (Valuable)
- Оцениваемость (Estimable)
- Небольшой размер (Small)
- Тестируемость (Testable)

## Задание 5: Use Case

Создайте use case для процесса "Оформление заказа" в системе электронной коммерции:
- Основной поток событий
- 3 альтернативных потока
- Предусловия
- Постусловия

## Задание 6: Критерии приемки

Напишите критерии приемки в формате Given-When-Then для функции "Восстановление пароля":
- Минимум 3 сценария (успешное восстановление, неверный email, истекший токен)

## Задание 7: Трассировка требований

Создайте матрицу трассировки требований, связывающую:
- 5 пользовательских требований
- 10 функциональных требований
- 3 use case
- 5 тест-кейсов
