## 1. Алгоритмы: восстановление кратчайшего пути в графе

```python
from collections import deque
from typing import List


def shortest_path_bfs(graph: List[List[int]], start: int, target: int) -> List[int]:
    n = len(graph)
    visited = [False] * n
    parent = [-1] * n
    queue = deque([start])
    visited[start] = True

    while queue:
        v = queue.popleft()
        if v == target:
            break
        for u in graph[v]:
            if not visited[u]:
                visited[u] = True
                parent[u] = v
                queue.append(u)

    if not visited[target]:
        return []

    path = []
    current = target
    while current != -1:
        path.append(current)
        current = parent[current]
    path.reverse()
    return path
```

**Объяснение:** Обход в ширину находит кратчайшие пути в невзвешенном графе. Массив `parent` позволяет восстановить путь от `target` назад к `start`, после чего путь разворачивается.

## 2. Алгоритмы: топологическая сортировка задач по зависимостям

```python
from typing import List
from collections import deque


def topological_sort_tasks(graph: List[List[int]], n: int) -> List[int]:
    in_degree = [0] * n
    for u in range(n):
        for v in graph[u]:
            in_degree[v] += 1

    queue = deque()
    for i in range(n):
        if in_degree[i] == 0:
            queue.append(i)

    order = []
    while queue:
        u = queue.popleft()
        order.append(u)
        for v in graph[u]:
            in_degree[v] -= 1
            if in_degree[v] == 0:
                queue.append(v)

    if len(order) != n:
        return []
    return order
```

**Объяснение:** Используется алгоритм Кана. Если удалось вынести в порядок все `n` вершин, граф ацикличен. Если остались вершины с ненулевой входящей степенью, значит есть цикл и корректного порядка нет.

## 3. Профилирование и оптимизация кода

**Анализ:** В исходной реализации используется двойной вложенный цикл по списку и дополнительная проверка `items[i] not in duplicates`. Это даёт квадратичную сложность по времени и дополнительный линейный поиск в списке `duplicates`.

Оптимизация: использовать словарь или множество для подсчёта количества вхождений элементов, а затем выбрать элементы, встречающиеся более одного раза.

```python
from typing import List, Any


def find_duplicates_optimized(items: List[Any]) -> List[Any]:
    counts = {}
    for item in items:
        counts[item] = counts.get(item, 0) + 1

    result = []
    for item, count in counts.items():
        if count > 1:
            result.append(item)
    return result
```

**Объяснение:** Подсчёт в словаре работает в среднем за амортизированное O(1) на элемент, поэтому общая сложность становится O(n) по числу элементов списка.

## 4. Nginx: reverse proxy и статика

```nginx
server {
    listen 80;
    server_name localhost;

    location /api/ {
        proxy_pass http://localhost:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        root /var/www/app_static;
        try_files $uri $uri/ =404;
    }
}
```

**Объяснение:** Блок `location /api/` проксирует запросы к приложению на порту 5000, а блок `location /` раздаёт статические файлы из указанной директории.

## 5. SQL: оконные функции и агрегирование

```sql
SELECT
    id,
    user_id,
    amount,
    paid_at,
    SUM(amount) OVER (
        PARTITION BY user_id
        ORDER BY paid_at
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS user_running_total,
    ROW_NUMBER() OVER (
        PARTITION BY user_id
        ORDER BY paid_at
    ) AS user_payment_number
FROM payments
ORDER BY user_id, paid_at;
```

**Объяснение:** Оконная функция `SUM` считает накопительный итог по пользователю, а `ROW_NUMBER` нумерует платежи пользователя в порядке времени.

## 6. MongoDB: агрегирование с $lookup

```javascript
db.orders.aggregate([
    {
        $lookup: {
            from: "products",
            localField: "product_id",
            foreignField: "_id",
            as: "product"
        }
    },
    {
        $unwind: "$product"
    },
    {
        $group: {
            _id: "$product.category",
            total_quantity: { $sum: "$quantity" }
        }
    },
    {
        $project: {
            _id: 0,
            category: "$_id",
            total_quantity: 1
        }
    },
    {
        $sort: { total_quantity: -1 }
    }
])
```

**Объяснение:** `$lookup` соединяет заказы с товарами, `$group` считает суммарное количество по категории, `$project` формирует итоговые поля, `$sort` сортирует по убыванию.

## 7. Pytest: fixtures и parametrize

```python
import pytest


class Calculator:
    def add(self, a, b):
        return a + b

    def divide(self, a, b):
        return a / b


@pytest.fixture
def calculator():
    return Calculator()


@pytest.mark.parametrize(
    "a,b,expected",
    [
        (1, 2, 3),
        (-1, 5, 4),
        (0, 0, 0),
    ],
)
def test_add(calculator, a, b, expected):
    assert calculator.add(a, b) == expected


def test_divide_by_zero(calculator):
    with pytest.raises(ZeroDivisionError):
        calculator.divide(1, 0)
```

**Объяснение:** Фикстура создаёт один экземпляр калькулятора для тестов, параметризация проверяет метод `add` на нескольких наборах данных, а конструкция `with pytest.raises` проверяет выброс исключения.

## 8. Юнит тесты: работа с репозиторием

Вариант на `pytest`:

```python
class UserRepository:
    def __init__(self):
        self._users = {}

    def add_user(self, user_id, name):
        self._users[user_id] = name

    def get_user(self, user_id):
        return self._users.get(user_id)


def test_add_and_get_user():
    repo = UserRepository()
    repo.add_user(1, "Alice")
    assert repo.get_user(1) == "Alice"


def test_get_unknown_user_returns_none():
    repo = UserRepository()
    assert repo.get_user(999) is None
```

**Объяснение:** Первый тест проверяет, что добавленный пользователь читается обратно с теми же данными, второй — что при запросе несуществующего пользователя возвращается `None`.

## 9. Docker: Dockerfile для Python-приложения

```dockerfile
FROM python:3.11-slim

WORKDIR /app

RUN adduser --disabled-password --gecos "" appuser

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

RUN chown -R appuser:appuser /app
USER appuser

CMD ["python", "main.py"]
```

**Объяснение:** Используется slim-образ для меньшего размера. Зависимости ставятся до копирования кода, чтобы слой кэшировался при неизменном `requirements.txt`. Пользователь `appuser` создаётся без пароля, права на `/app` передаются ему, затем переключение на него. `--no-cache-dir` уменьшает размер образа.
