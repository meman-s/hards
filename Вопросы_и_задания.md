## 11. Тестирование

### Вопрос
Объясните пирамиду тестирования. Какое соотношение unit, integration и E2E тестов должно быть? Почему?

### Задания

#### Pytest: fixtures, parametrize, markers
Создайте тестовый набор используя:
1. Fixtures для подготовки данных (БД, файлы)
2. Parametrize для тестирования с разными входными данными
3. Markers для категоризации тестов
4. Плагины и кастомные фикстуры

#### Юнит тесты
Напишите unit тесты для:
1. Функций валидации данных
2. Бизнес-логики (расчеты, преобразования)
3. Утилитарных функций
4. Мокирование зависимостей

#### Интеграционные тесты
Создайте интеграционные тесты:
1. Тестирование API эндпоинтов с реальной БД
2. Тестирование взаимодействия сервисов
3. Тестирование работы с внешними API (моки)
4. Тестирование миграций БД

#### E2E тесты: Selenium или Playwright
Создайте E2E тесты используя Playwright:
1. Тест регистрации пользователя
2. Тест процесса покупки товара
3. Тест работы с формами
4. Скриншоты и видео при падении тестов

## 12. Развертывание

### Вопрос
Опишите процесс CI/CD от коммита кода до развертывания в production. Какие этапы должны быть включены?

### Задания

#### Docker: multi-stage builds, secrets, ssh mount
Создайте Dockerfile с:
1. Multi-stage build для оптимизации размера образа
2. Использование secrets для чувствительных данных
3. SSH mount для доступа к приватным репозиториям
4. Оптимизация слоев и кеширования

#### Docker Compose: healthcheck, services, networks, volumes
Создайте docker-compose.yml для:
1. Веб-приложения (FastAPI)
2. Базы данных (PostgreSQL)
3. Кеша (Redis)
4. Healthchecks для всех сервисов
5. Сети и volumes для данных

#### RabbitMQ
Настройте RabbitMQ для:
1. Очереди задач для фоновой обработки
2. Pub/Sub для уведомлений
3. Распределение нагрузки между воркерами
4. Обработка ошибок и retry механизм

#### Спецификация Семантического Версионирования (SemVer)
Определите версии для следующих изменений:
1. Исправление критического бага
2. Добавление новой функции
3. Изменение API с обратной совместимостью
4. Breaking changes в API
5. Настройка автоматического версионирования в CI/CD

#### CI/CD
Настройте CI/CD pipeline:
1. Автоматический запуск тестов при push
2. Проверка качества кода (linting, type checking)
3. Сборка Docker образа
4. Развертывание на staging окружение
5. Ручное подтверждение для production
6. Откат при ошибках
