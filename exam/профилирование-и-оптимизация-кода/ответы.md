## Задание 1: Неэффективный поиск в списке

### Проблема
- Поиск пользователя по email выполняется за O(n) для каждого вызова
- При 1000 поисках в списке из 10000 элементов выполняется 10,000,000 операций сравнения
- Использование списка вместо словаря для поиска неэффективно

### Оптимизированный код
```python
class UserService:
    def __init__(self):
        self.users = []
        self.email_index = {}
    
    def add_user(self, name, email):
        user = {"name": name, "email": email}
        self.users.append(user)
        self.email_index[email] = user
    
    def find_user_by_email(self, email):
        return self.email_index.get(email)
    
    def get_user_statistics(self):
        stats = {}
        for user in self.users:
            domain = user["email"].split("@")[1]
            stats[domain] = stats.get(domain, 0) + 1
        return stats
```

### Объяснение
- **Было**: O(n) для каждого поиска, общая сложность O(n × m) где n - размер списка, m - количество поисков
- **Стало**: O(1) для каждого поиска, общая сложность O(n + m)
- Использован словарь (хеш-таблица) для индексации по email
- При добавлении пользователя обновляется индекс
- Поиск теперь выполняется за константное время

## Задание 2: N+1 проблема с базой данных

### Проблема
- Для каждого заказа выполняется отдельный запрос к базе данных для получения информации о клиенте
- При N заказах выполняется 1 + N запросов (N+1 проблема)
- Это приводит к большому количеству обращений к БД и медленной работе

### Оптимизированный код
```python
class OrderService:
    def __init__(self, db):
        self.db = db
    
    def get_orders_with_customers(self):
        orders = self.db.query("SELECT id, customer_id, total FROM orders")
        
        if not orders:
            return []
        
        customer_ids = [order['customer_id'] for order in orders]
        placeholders = ','.join(map(str, customer_ids))
        customers_query = f"SELECT id, name, email FROM customers WHERE id IN ({placeholders})"
        customers = self.db.query(customers_query)
        
        customer_dict = {c['id']: c for c in customers}
        
        result = []
        for order in orders:
            customer = customer_dict.get(order['customer_id'])
            if customer:
                result.append({
                    "order_id": order["id"],
                    "total": order["total"],
                    "customer_name": customer["name"],
                    "customer_email": customer["email"]
                })
        return result
```

### Объяснение
- **Было**: 1 запрос для заказов + N запросов для клиентов = N+1 запросов
- **Стало**: 1 запрос для заказов + 1 запрос для всех клиентов = 2 запроса
- Использован JOIN или IN-запрос для получения всех клиентов одним запросом
- Данные клиентов кэшируются в словаре для быстрого доступа
- Количество запросов уменьшено с O(n) до O(1)

## Задание 3: Неэффективная работа со строками

### Проблема
- Конкатенация строк через оператор `+=` создает новую строку при каждой операции
- В Python строки неизменяемы, поэтому каждая конкатенация создает новый объект
- При обработке длинного текста это приводит к квадратичной сложности O(n²)

### Оптимизированный код
```python
def process_text(text):
    import re
    from collections import Counter
    
    words = re.findall(r'\w+', text)
    stats = Counter(word.lower() for word in words)
    
    return dict(stats)
```

### Альтернативное решение (без regex)
```python
def process_text(text):
    words = []
    current_word = []
    
    for char in text:
        if char.isalnum():
            current_word.append(char)
        else:
            if current_word:
                words.append(''.join(current_word))
                current_word = []
    
    if current_word:
        words.append(''.join(current_word))
    
    stats = {}
    for word in words:
        word_lower = word.lower()
        stats[word_lower] = stats.get(word_lower, 0) + 1
    
    return stats
```

### Объяснение
- **Было**: O(n²) из-за конкатенации строк через `+=`
- **Стало**: O(n) с использованием списка символов и `join()` или регулярных выражений
- Использован список для накопления символов слова, затем `join()` для создания строки
- `Counter` из `collections` оптимизирован для подсчета частоты элементов
- Регулярные выражения эффективны для парсинга текста

## Задание 4: Избыточные вычисления и кэширование

### Проблема
- Факториал вычисляется заново для каждого числа, даже если оно уже вычислялось
- Рекурсивный вызов без мемоизации приводит к повторным вычислениям
- При повторяющихся значениях выполняется много избыточной работы

### Оптимизированный код
```python
from functools import lru_cache

@lru_cache(maxsize=None)
def factorial(n):
    if n <= 1:
        return 1
    return n * factorial(n - 1)

def process_numbers(numbers):
    results = []
    for num in numbers:
        results.append(factorial(num))
    return results
```

### Альтернативное решение (ручная мемоизация)
```python
def factorial_memoized():
    cache = {}
    
    def factorial(n):
        if n in cache:
            return cache[n]
        if n <= 1:
            result = 1
        else:
            result = n * factorial(n - 1)
        cache[n] = result
        return result
    
    return factorial

factorial = factorial_memoized()

def process_numbers(numbers):
    results = []
    for num in numbers:
        results.append(factorial(num))
    return results
```

### Объяснение
- **Было**: Каждое вычисление факториала выполняется независимо, даже для одинаковых значений
- **Стало**: Результаты кэшируются, повторные вычисления для одинаковых значений выполняются за O(1)
- Использован декоратор `@lru_cache` для автоматической мемоизации
- При первом вычислении результат сохраняется в кэше
- Последующие вызовы с теми же аргументами возвращают значение из кэша
- Ускорение особенно заметно при повторяющихся значениях

## Задание 5: Проблемы с памятью при обработке больших файлов

### Проблема
- `readlines()` загружает весь файл в память сразу
- При больших файлах это может привести к нехватке памяти (MemoryError)
- Обработка происходит только после полной загрузки файла

### Оптимизированный код
```python
def process_large_file(filename):
    processed = []
    
    with open(filename, 'r') as f:
        for line in f:
            processed.append(line.strip().upper())
    
    return processed
```

### Еще более оптимизированное решение (генератор)
```python
def process_large_file_generator(filename):
    with open(filename, 'r') as f:
        for line in f:
            yield line.strip().upper()

def process_large_file(filename):
    return list(process_large_file_generator(filename))
```

### Объяснение
- **Было**: Весь файл загружается в память через `readlines()`, потребление памяти O(n) где n - размер файла
- **Стало**: Файл обрабатывается построчно, потребление памяти O(1) для каждой строки
- Итерация по файловому объекту читает файл построчно, не загружая его полностью
- Генератор позволяет обрабатывать файл без сохранения всех результатов в памяти
- Подходит для файлов любого размера, ограничение только по размеру одной строки

## Задание 6: Неэффективная сортировка и фильтрация

### Проблема
- Использована пузырьковая сортировка с временной сложностью O(n²)
- Фильтрация выполняется через цикл с append, что менее эффективно чем list comprehension
- Можно использовать встроенные функции Python, которые оптимизированы на C

### Оптимизированный код
```python
class ProductService:
    def __init__(self):
        self.products = []
    
    def add_product(self, name, price, category):
        self.products.append({
            "name": name,
            "price": price,
            "category": category
        })
    
    def get_expensive_products(self, min_price):
        expensive = [
            product for product in self.products 
            if product["price"] >= min_price
        ]
        
        expensive.sort(key=lambda x: x["price"], reverse=True)
        
        return expensive
```

### Объяснение
- **Было**: 
  - Пузырьковая сортировка: O(n²)
  - Фильтрация через цикл: менее эффективна
- **Стало**:
  - Встроенная сортировка Timsort: O(n log n) в худшем случае, O(n) для частично отсортированных данных
  - List comprehension: оптимизирован на уровне интерпретатора
- Использован `list.sort()` с ключом для сортировки по цене
- List comprehension быстрее обычного цикла с append
- Встроенные функции Python написаны на C и работают быстрее чистого Python кода

## Задание 7: Неэффективное использование списков

### Проблема
- `list.insert(0, item)` имеет сложность O(n), так как все элементы нужно сдвинуть
- При добавлении N элементов в начало списка общая сложность O(n²)
- Использование срезов для получения последних элементов менее эффективно, чем нужно

### Оптимизированный код
```python
def reverse_list(items):
    return list(reversed(items))

def get_last_n_items(items, n):
    return items[-n:]
```

### Объяснение
- **Было**: O(n²) из-за insert(0, ...) в цикле
- **Стало**: O(n) с использованием reversed() и срезов
- `reversed()` возвращает итератор, который работает за O(1) для создания и O(n) для преобразования в список
- Срезы `items[-n:]` работают за O(n), но это одна операция вместо цикла
- Для операций с начала списка можно использовать `collections.deque` с O(1) операциями

## Задание 8: Избыточные проверки и условия

### Проблема
- Условия `filter_enabled` и `transform_enabled` проверяются на каждой итерации цикла
- Эти значения не меняются в процессе выполнения, но проверяются тысячи раз
- Вложенные условия усложняют код и замедляют выполнение

### Оптимизированный код
```python
def process_items(items, filter_enabled, transform_enabled):
    if filter_enabled and transform_enabled:
        return [item * 2 for item in items if item > 0]
    elif filter_enabled:
        return [item for item in items if item > 0]
    elif transform_enabled:
        return [item * 2 for item in items]
    else:
        return list(items)
```

### Объяснение
- **Было**: Проверка условий на каждой итерации цикла, O(n) проверок
- **Стало**: Проверка условий один раз перед циклом, O(1) проверок
- Условия вынесены за пределы цикла, код выполняется по одной из четырех веток
- List comprehension быстрее обычного цикла с append
- Код стал проще и читабельнее

## Задание 9: Неэффективная работа со словарями

### Проблема
- Множественные проверки `if key not in dict` перед каждым обращением
- Двойное или тройное обращение к словарю для одной операции
- Избыточный код для инициализации значений

### Оптимизированный код
```python
from collections import defaultdict

def count_items(items):
    stats = defaultdict(int)
    for item in items:
        stats[item] += 1
    return dict(stats)

def merge_dicts(dict1, dict2):
    result = defaultdict(int)
    for key, value in dict1.items():
        result[key] = value
    for key, value in dict2.items():
        result[key] += value
    return dict(result)
```

### Альтернативное решение (без defaultdict)
```python
def count_items(items):
    stats = {}
    for item in items:
        stats[item] = stats.get(item, 0) + 1
    return stats

def merge_dicts(dict1, dict2):
    result = dict(dict1)
    for key, value in dict2.items():
        result[key] = result.get(key, 0) + value
    return result
```

### Объяснение
- **Было**: 2-3 обращения к словарю на каждую операцию (проверка + чтение + запись)
- **Стало**: 1 обращение к словарю на операцию
- `defaultdict(int)` автоматически инициализирует отсутствующие ключи значением 0
- `dict.get(key, default)` позволяет избежать проверки наличия ключа
- Код стал короче и эффективнее

## Задание 10: Неэффективное использование генераторов

### Проблема
- Множественные проходы по данным: создание списка, фильтрация, сортировка
- Функция статистики делает 4 прохода по данным (sum, len, max, min)
- Создание промежуточных списков потребляет лишнюю память

### Оптимизированный код
```python
def process_data(data):
    filtered_squared = (x ** 2 for x in data if x ** 2 > 100)
    return sorted(filtered_squared)

def get_statistics(data):
    total = 0
    count = 0
    max_val = float('-inf')
    min_val = float('inf')
    
    for item in data:
        total += item
        count += 1
        if item > max_val:
            max_val = item
        if item < min_val:
            min_val = item
    
    average = total / count if count > 0 else 0
    
    return {
        "total": total,
        "count": count,
        "average": average,
        "max": max_val,
        "min": min_val
    }
```

### Объяснение
- **Было**: 
  - process_data: 3 прохода по данным (создание, фильтрация, сортировка)
  - get_statistics: 4 прохода (sum, len, max, min)
- **Стало**:
  - process_data: 1 проход с генератором, затем сортировка
  - get_statistics: 1 проход с вычислением всех метрик одновременно
- Генератор `(x ** 2 for x in data if x ** 2 > 100)` не создает промежуточный список
- Все метрики вычисляются за один проход по данным
- Потребление памяти уменьшено, скорость выполнения увеличена
