# Теория сложности алгоритмов

## Введение

Сложность алгоритма — это мера количества ресурсов (времени или памяти), необходимых для выполнения алгоритма в зависимости от размера входных данных.

## Виды сложности

### 1. Временная сложность (Time Complexity)

Временная сложность описывает, как время выполнения алгоритма зависит от размера входных данных.

#### Примеры временной сложности:

- **O(1)** — константная сложность
  - Время выполнения не зависит от размера входных данных
  - Пример: доступ к элементу массива по индексу
  ```python
  def get_first_element(arr):
      return arr[0]  # O(1)
  ```

- **O(log n)** — логарифмическая сложность
  - Время растет логарифмически от размера данных
  - Пример: бинарный поиск
  ```python
  def binary_search(arr, target):
      left, right = 0, len(arr) - 1
      while left <= right:
          mid = (left + right) // 2
          if arr[mid] == target:
              return mid
          elif arr[mid] < target:
              left = mid + 1
          else:
              right = mid - 1
      return -1  # O(log n)
  ```

- **O(n)** — линейная сложность
  - Время пропорционально размеру входных данных
  - Пример: поиск элемента в неотсортированном массиве
  ```python
  def find_element(arr, target):
      for item in arr:
          if item == target:
              return True
      return False  # O(n)
  ```

- **O(n log n)** — линейно-логарифмическая сложность
  - Часто встречается в эффективных алгоритмах сортировки
  - Пример: сортировка слиянием, быстрая сортировка (в среднем)
  ```python
  def merge_sort(arr):
      if len(arr) <= 1:
          return arr
      mid = len(arr) // 2
      left = merge_sort(arr[:mid])  # O(n log n)
      right = merge_sort(arr[mid:])
      return merge(left, right)
  ```

- **O(n²)** — квадратичная сложность
  - Время пропорционально квадрату размера данных
  - Пример: пузырьковая сортировка, вложенные циклы
  ```python
  def bubble_sort(arr):
      n = len(arr)
      for i in range(n):
          for j in range(0, n - i - 1):
              if arr[j] > arr[j + 1]:
                  arr[j], arr[j + 1] = arr[j + 1], arr[j]  # O(n²)
  ```

- **O(2ⁿ)** — экспоненциальная сложность
  - Время растет экспоненциально
  - Пример: рекурсивное вычисление чисел Фибоначчи без мемоизации
  ```python
  def fibonacci(n):
      if n <= 1:
          return n
      return fibonacci(n - 1) + fibonacci(n - 2)  # O(2ⁿ)
  ```

- **O(n!)** — факториальная сложность
  - Самая медленная сложность
  - Пример: генерация всех перестановок
  ```python
  def permutations(arr):
      if len(arr) <= 1:
          return [arr]
      result = []
      for i in range(len(arr)):
          rest = arr[:i] + arr[i+1:]
          for p in permutations(rest):
              result.append([arr[i]] + p)
      return result  # O(n!)
  ```

### 2. Пространственная сложность (Space Complexity)

Пространственная сложность описывает, сколько дополнительной памяти требуется алгоритму в зависимости от размера входных данных.

#### Примеры:

- **O(1)** — константная память
  - Алгоритм использует фиксированное количество памяти
  ```python
  def find_max(arr):
      max_val = arr[0]
      for item in arr:
          if item > max_val:
              max_val = item
      return max_val  # O(1) дополнительной памяти
  ```

- **O(n)** — линейная память
  - Память пропорциональна размеру входных данных
  ```python
  def copy_array(arr):
      result = []
      for item in arr:
          result.append(item)
      return result  # O(n) дополнительной памяти
  ```

- **O(n²)** — квадратичная память
  - Память пропорциональна квадрату размера данных
  ```python
  def create_matrix(n):
      matrix = []
      for i in range(n):
          row = []
          for j in range(n):
              row.append(i * j)
          matrix.append(row)
      return matrix  # O(n²) памяти
  ```

## Асимптотические обозначения

### 1. Big O (O) — верхняя граница

**O(f(n))** означает, что алгоритм выполняется не медленнее, чем f(n) при достаточно больших n.

Формальное определение:
```
T(n) = O(f(n)), если существуют константы c > 0 и n₀ > 0 такие, что
T(n) ≤ c × f(n) для всех n ≥ n₀
```

**Пример:**
- Если алгоритм имеет сложность O(n²), это означает, что в худшем случае он выполняется за время, пропорциональное n²
- Но может быть и быстрее (например, O(n) или O(1))

### 2. Big Omega (Ω) — нижняя граница

**Ω(f(n))** означает, что алгоритм выполняется не быстрее, чем f(n) при достаточно больших n.

Формальное определение:
```
T(n) = Ω(f(n)), если существуют константы c > 0 и n₀ > 0 такие, что
T(n) ≥ c × f(n) для всех n ≥ n₀
```

**Пример:**
- Если алгоритм имеет сложность Ω(n), это означает, что даже в лучшем случае он требует времени, пропорционального n
- Например, поиск элемента в неотсортированном массиве имеет Ω(n), так как нужно проверить все элементы в худшем случае

### 3. Big Theta (Θ) — точная граница

**Θ(f(n))** означает, что алгоритм имеет как верхнюю, так и нижнюю границу f(n).

Формальное определение:
```
T(n) = Θ(f(n)), если T(n) = O(f(n)) и T(n) = Ω(f(n))
```

**Пример:**
- Сортировка слиянием имеет сложность Θ(n log n)
- Это означает, что алгоритм всегда выполняется за время, пропорциональное n log n (и в лучшем, и в худшем случае)

### Сравнение обозначений:

```
O(n)    — "не более чем n"
Ω(n)    — "не менее чем n"
Θ(n)    — "точно n"
```

## Анализ по случаям

### 1. Лучший случай (Best Case)

Минимальное время выполнения при наиболее благоприятных входных данных.

**Пример:**
```python
def linear_search(arr, target):
    for i, item in enumerate(arr):
        if item == target:
            return i  # Лучший случай: O(1) если элемент первый
    return -1
```

### 2. Средний случай (Average Case)

Ожидаемое время выполнения при случайных входных данных.

**Пример:**
- Линейный поиск: средний случай O(n/2) = O(n)
- Быстрая сортировка: средний случай O(n log n)

### 3. Худший случай (Worst Case)

Максимальное время выполнения при наиболее неблагоприятных входных данных.

**Пример:**
```python
def linear_search(arr, target):
    for i, item in enumerate(arr):
        if item == target:
            return i
    return -1  # Худший случай: O(n) если элемента нет или он последний
```

## Амортизированная сложность (Amortized Complexity)

Амортизированная сложность показывает среднюю стоимость операции в последовательности операций, даже если отдельные операции могут быть дорогими.

### Пример: динамический массив (list в Python)

```python
arr = []
for i in range(n):
    arr.append(i)  # Большинство операций O(1), но некоторые O(n)
```

**Анализ:**
- Большинство операций `append()` выполняются за O(1)
- Когда массив переполняется, происходит перераспределение памяти за O(n)
- Но перераспределение происходит редко (каждые n операций)
- **Амортизированная сложность: O(1)** на операцию

### Метод агрегации:

Если последовательность из n операций занимает время T(n), то амортизированная стоимость одной операции равна T(n)/n.

## Практические примеры анализа сложности

### Пример 1: Вложенные циклы

```python
def process_matrix(matrix):
    n = len(matrix)
    for i in range(n):           # O(n)
        for j in range(n):       # O(n)
            matrix[i][j] *= 2    # O(1)
    # Общая сложность: O(n) × O(n) × O(1) = O(n²)
```

### Пример 2: Последовательные операции

```python
def process_data(arr):
    arr.sort()                    # O(n log n)
    for item in arr:              # O(n)
        print(item)               # O(1)
    # Общая сложность: O(n log n) + O(n) = O(n log n)
```

### Пример 3: Условные операции

```python
def search(arr, target):
    if len(arr) == 0:
        return -1                 # O(1)
    arr.sort()                    # O(n log n)
    # бинарный поиск              # O(log n)
    # Общая сложность: O(n log n) (доминирующая операция)
```

## Правила упрощения

1. **Константы игнорируются:**
   - O(2n) = O(n)
   - O(100) = O(1)

2. **Младшие члены игнорируются:**
   - O(n² + n) = O(n²)
   - O(n + log n) = O(n)

3. **Доминирующий член:**
   - При анализе выбирается самый быстрорастущий член

## Инструменты для измерения сложности

### 1. Профилирование времени

```python
import time

def measure_time(func, *args):
    start = time.perf_counter()
    result = func(*args)
    end = time.perf_counter()
    return result, end - start
```

### 2. Профилирование памяти

```python
import tracemalloc

def measure_memory(func, *args):
    tracemalloc.start()
    result = func(*args)
    current, peak = tracemalloc.get_traced_memory()
    tracemalloc.stop()
    return result, peak
```

### 3. cProfile

```python
import cProfile

cProfile.run('your_function()')
```

## Заключение

Понимание сложности алгоритмов критически важно для:
- Выбора правильного алгоритма для задачи
- Оптимизации производительности
- Предсказания поведения при росте данных
- Проектирования масштабируемых систем

Помните:
- **Асимптотическая сложность** показывает поведение при больших n
- **Практическая производительность** может отличаться из-за константных факторов
- Всегда измеряйте реальную производительность на реальных данных
- Пространственная сложность так же важна, как временная
