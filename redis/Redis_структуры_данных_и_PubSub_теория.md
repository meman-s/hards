Redis: структуры данных и Pub/Sub

Введение

Redis — это высокопроизводительное хранилище данных в памяти с поддержкой различных структур данных и механизмом Pub/Sub для обмена сообщениями. Чаще всего его используют как кэш, брокер сообщений, счетчики и хранилище временных данных.

Ключевые особенности:
- Работа в памяти с возможностью периодической записи на диск
- Богатые структуры данных
- Простые и предсказуемые команды
- Однопоточная модель исполнения команд

Базовая модель данных

Redis работает по принципу ключ-значение. Ключ — всегда строка, а значение может быть одной из поддерживаемых структур данных: String, Hash, List, Set, Sorted Set и другие.

String

String — самая простая и самая часто используемая структура данных в Redis.

Типичные применения:
- Счетчики (просмотры страницы, количество логинов)
- Кэширование произвольных значений (JSON, токены)
- Хранение небольших текстов

Основные команды:
- SET key value — установить значение
- GET key — получить значение
- INCR key — увеличить значение на 1 (предполагается, что это число)
- DECR key — уменьшить значение на 1
- INCRBY key n — увеличить значение на n
- EXPIRE key seconds — установить время жизни ключа

Примеры:
- Счетчик просмотров:
  - INCR page:123:views
- Кэш токена с TTL:
  - SET user:10:token abc123 EX 3600

Hash

Hash — это ассоциативный массив (словарь), где внутри одного ключа Redis хранится набор полей и значений.

Типичные применения:
- Профили пользователей
- Настройки сущностей
- Объекты с фиксированным набором полей

Основные команды:
- HSET key field value — установить значение поля
- HGET key field — получить значение поля
- HGETALL key — получить все поля и значения
- HMSET key field1 value1 field2 value2 — установить несколько полей
- HDEL key field — удалить поле

Примеры:
- Профиль пользователя:
  - HSET user:42 name "Ivan"
  - HSET user:42 email "ivan@example.com"
  - HGETALL user:42

Плюсы Hash:
- Удобно групировать связанные данные
- Можно обновлять отдельные поля без перезаписи всего объекта

List

List — связанный список, упорядоченный по вставке. Поддерживает операции с обеих сторон (лево и право).

Типичные применения:
- Очереди задач
- Списки событий или логов
- Хронологические ленты

Основные команды:
- LPUSH key value — добавить элемент слева
- RPUSH key value — добавить элемент справа
- LPOP key — извлечь элемент слева
- RPOP key — извлечь элемент справа
- LRANGE key start stop — получить диапазон элементов по индексам

Примеры:
- Очередь задач:
  - RPUSH queue:emails task1
  - RPUSH queue:emails task2
  - LPOP queue:emails

Особенности:
- List сохраняет порядок
- Удобен для реализации очередей, но не оптимален для поиска по содержимому

Set

Set — неупорядоченное множество уникальных элементов.

Типичные применения:
- Множества тегов или ролей
- Списки друзей/подписок
- Уникальные значения (например, уникальные IP-адреса)

Основные команды:
- SADD key value — добавить элемент
- SREM key value — удалить элемент
- SMEMBERS key — получить все элементы множества
- SISMEMBER key value — проверить, есть ли элемент в множестве
- SUNION key1 key2 — объединение двух множеств
- SINTER key1 key2 — пересечение двух множеств

Примеры:
- Теги пользователя:
  - SADD user:10:tags "python" "backend"
  - SISMEMBER user:10:tags "python"

Плюсы Set:
- Гарантирует уникальность
- Поддерживает операции над множествами (объединение, пересечение, разность)

Sorted Set (ZSet)

Sorted Set — это множество уникальных элементов, где каждому элементу сопоставлен числовой score, по которому множество упорядочено.

Типичные применения:
- Рейтинги и топы (лидерборды)
- Очереди с приоритетом
- Отложенные задачи (по времени в виде score)

Основные команды:
- ZADD key score member — добавить элемент с заданным score
- ZRANGE key start stop [WITHSCORES] — получить элементы по индексам по возрастанию score
- ZREVRANGE key start stop [WITHSCORES] — получить элементы по убыванию score
- ZRANGEBYSCORE key min max — получить элементы по диапазону score
- ZREM key member — удалить элемент

Примеры:
- Лидерборд по очкам:
  - ZADD leaderboard 100 "user1"
  - ZADD leaderboard 200 "user2"
  - ZREVRANGE leaderboard 0 2 WITHSCORES

Особенности:
- Уникальность элементов как в Set
- Упорядочивание по score

Pub/Sub

Pub/Sub — механизм обмена сообщениями между издателями и подписчиками.

Принцип работы:
- Издатель отправляет сообщения в канал (channel)
- Подписчики слушают один или несколько каналов
- Сообщения не сохраняются — только доставляются текущим подписчикам

Основные команды:
- SUBSCRIBE channel — подписаться на канал
- UNSUBSCRIBE channel — отписаться от канала
- PUBLISH channel message — отправить сообщение в канал

Пример сценария:
- Один сервис формирует события:
  - PUBLISH notifications "user 10 logged in"
- Другой сервис подписан:
  - SUBSCRIBE notifications
- Каждый полученный message обрабатывается в реальном времени

Важно:
- Pub/Sub — это механизм доставки событий, но не долговременное хранилище
- Если получатель не подписан в момент публикации — сообщение теряется

Комбинирование структур

В реальных задачах обычно комбинируют несколько структур данных:
- String как счетчики
- Hash для хранения атрибутов сущностей
- Set для тегов и связей многие-ко-многим
- Sorted Set для рейтингов и сортировки по времени или весу
- Pub/Sub для нотификаций и событийной интеграции

Пример общей схемы:
- user:42 — Hash с полями профиля
- user:42:tags — Set тегов пользователя
- leaderboard:points — Sorted Set с очками пользователей
- notifications — канал Pub/Sub для уведомлений о событиях
