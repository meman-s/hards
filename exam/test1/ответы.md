## 1. Обход неориентированного графа в ширину

```python
from collections import deque
from typing import List

def bfs_undirected(graph: List[List[int]], start: int) -> List[int]:
    n = len(graph)
    order = []
    visited = [False] * n
    queue = deque([start])
    visited[start] = True
    
    while queue:
        v = queue.popleft()
        order.append(v)
        for u in graph[v]:
            if not visited[u]:
                visited[u] = True
                queue.append(u)
    
    return order
```

**Объяснение:** Используется очередь (deque) для обхода графа в ширину. Вершины посещаются по уровням: сначала стартовая, затем все её соседи, затем соседи соседей и т.д.

## 2. Обход неориентированного графа в глубину

```python
from typing import List

def dfs_undirected(graph: List[List[int]], start: int) -> List[int]:
    n = len(graph)
    order = []
    visited = [False] * n
    
    def dfs(v):
        visited[v] = True
        order.append(v)
        for u in graph[v]:
            if not visited[u]:
                dfs(u)
    
    dfs(start)
    return order
```

**Объяснение:** Используется рекурсивный обход в глубину. Для каждой вершины сначала обрабатываем её, затем рекурсивно обрабатываем всех непосещённых соседей.

## 3. Обход ориентированного графа в ширину

```python
from collections import deque
from typing import List, Set

def bfs_directed(graph: List[List[int]], start: int) -> Set[int]:
    n = len(graph)
    visited = set()
    queue = deque([start])
    visited.add(start)
    
    while queue:
        v = queue.popleft()
        for u in graph[v]:
            if u not in visited:
                visited.add(u)
                queue.append(u)
    
    return visited
```

**Объяснение:** Аналогично BFS для неориентированного графа, но учитываем направленность рёбер. Используем множество для хранения достижимых вершин.

## 4. Обход ориентированного графа в глубину

```python
from typing import List

def dfs_directed(graph: List[List[int]], start: int, target: int) -> bool:
    n = len(graph)
    visited = [False] * n
    
    def dfs(v):
        if v == target:
            return True
        visited[v] = True
        for u in graph[v]:
            if not visited[u]:
                if dfs(u):
                    return True
        return False
    
    return dfs(start)
```

**Объяснение:** Используется рекурсивный DFS для поиска пути. Если достигли целевой вершины, возвращаем True. Если все пути из текущей вершины исследованы и путь не найден, возвращаем False.

## 5. Топологическая сортировка

```python
from typing import List

def topological_sort(graph: List[List[int]], n: int) -> List[int]:
    in_degree = [0] * n
    for u in range(n):
        for v in graph[u]:
            in_degree[v] += 1
    
    queue = []
    for i in range(n):
        if in_degree[i] == 0:
            queue.append(i)
    
    result = []
    while queue:
        u = queue.pop(0)
        result.append(u)
        for v in graph[u]:
            in_degree[v] -= 1
            if in_degree[v] == 0:
                queue.append(v)
    
    return result
```

**Объяснение:** Используется алгоритм Кана. Сначала считаем входящие степени всех вершин. Затем добавляем в очередь все вершины с нулевой входящей степенью. На каждом шаге извлекаем вершину из очереди, добавляем в результат и уменьшаем входящие степени её соседей.

## 6. Обход графа (дополнительное задание)

```python
from typing import List

def count_components(graph: List[List[int]], n: int) -> int:
    visited = [False] * n
    count = 0
    
    def dfs(v):
        visited[v] = True
        for u in graph[v]:
            if not visited[u]:
                dfs(u)
    
    for i in range(n):
        if not visited[i]:
            count += 1
            dfs(i)
    
    return count
```

**Объяснение:** Для каждой непосещённой вершины запускаем DFS, который помечает все вершины в той же компоненте связности. Количество запусков DFS равно количеству компонент.

## 7. Профилирование и оптимизация кода

**Узкое место:** Проверка всех чисел от 2 до num для каждого числа. Это даёт сложность O(n²).

**Оптимизированная версия:**

```python
def find_primes(n):
    if n < 2:
        return []
    
    primes = []
    is_prime = [True] * (n + 1)
    is_prime[0] = is_prime[1] = False
    
    for i in range(2, int(n ** 0.5) + 1):
        if is_prime[i]:
            for j in range(i * i, n + 1, i):
                is_prime[j] = False
    
    for i in range(2, n + 1):
        if is_prime[i]:
            primes.append(i)
    
    return primes
```

**Объяснение:** Используется решето Эратосфена с оптимизацией. Сложность O(n log log n). Проверяем только до √n и начинаем вычёркивать с i².

## 10. MongoDB: Агрегация с $lookup

```javascript
db.orders.aggregate([
    {
        $lookup: {
            from: "customers",
            localField: "customer_id",
            foreignField: "_id",
            as: "customer"
        }
    },
    {
        $unwind: "$customer"
    },
    {
        $group: {
            _id: "$customer_id",
            customer_name: { $first: "$customer.name" },
            total_amount: { $sum: "$total" }
        }
    },
    {
        $sort: { total_amount: -1 }
    },
    {
        $project: {
            _id: 0,
            customer_name: 1,
            total_amount: 1
        }
    }
])
```

**Объяснение:**
- `$lookup` объединяет заказы с клиентами
- `$unwind` разворачивает массив customer
- `$group` группирует по клиенту и считает сумму
- `$sort` сортирует по убыванию суммы
- `$project` выбирает нужные поля

## 11. Pytest: fixtures и parametrize

```python
import pytest

@pytest.fixture
def calculator():
    return Calculator()

@pytest.mark.parametrize("a, b, expected", [
    (2, 3, 5),
    (0, 0, 0),
    (-1, 1, 0),
    (10, -5, 5),
])
def test_add(calculator, a, b, expected):
    assert calculator.add(a, b) == expected

def test_multiply(calculator):
    assert calculator.multiply(3, 4) == 12

def test_divide(calculator):
    assert calculator.divide(10, 2) == 5

def test_divide_by_zero(calculator):
    with pytest.raises(ValueError, match="Division by zero"):
        calculator.divide(10, 0)
```

**Объяснение:**
- Фикстура `calculator` создаёт экземпляр для каждого теста
- `@pytest.mark.parametrize` тестирует `add` с разными данными
- `pytest.raises` проверяет исключение при делении на ноль

## 12. Юнит тесты

```python
import unittest

class TestValidateEmail(unittest.TestCase):
    
    def test_valid_emails(self):
        valid_emails = [
            "test@example.com",
            "user.name@domain.co.uk",
            "user+tag@example.org"
        ]
        for email in valid_emails:
            with self.subTest(email=email):
                self.assertTrue(validate_email(email))
    
    def test_empty_string(self):
        self.assertFalse(validate_email(""))
    
    def test_no_at_symbol(self):
        self.assertFalse(validate_email("testexample.com"))
    
    def test_multiple_at_symbols(self):
        self.assertFalse(validate_email("test@@example.com"))
    
    def test_no_local_part(self):
        self.assertFalse(validate_email("@example.com"))
    
    def test_no_domain_part(self):
        self.assertFalse(validate_email("test@"))
    
    def test_no_dot_in_domain(self):
        self.assertFalse(validate_email("test@example"))
    
    def test_dot_at_start_of_domain(self):
        self.assertFalse(validate_email("test@.example.com"))

if __name__ == '__main__':
    unittest.main()
```

**Объяснение:** Тесты покрывают все граничные случаи: валидные email, пустая строка, отсутствие символов @ и точки, некорректные части адреса.

## 13. Docker: multi-stage builds и secrets

```dockerfile
FROM python:3.9-slim as builder
WORKDIR /app
COPY requirements.txt .
RUN --mount=type=secret,id=github_token \
    pip install --no-cache-dir -r requirements.txt

FROM python:3.9-slim
WORKDIR /app
COPY --from=builder /usr/local/lib/python3.9/site-packages /usr/local/lib/python3.9/site-packages
COPY --from=builder /usr/local/bin /usr/local/bin
COPY . .
CMD ["python", "app.py"]
```

**Объяснение:**
- `builder` stage устанавливает зависимости
- `--mount=type=secret` использует секреты для приватных пакетов
- Runtime stage копирует только необходимые файлы, минимизируя размер образа

**Использование:**
```bash
docker build --secret id=github_token,src=./token.txt -t myapp .
```

## 14. Docker Compose: healthcheck, networks, volumes

```yaml
version: '3.8'

services:
  web:
    image: nginx:alpine
    ports:
      - "80:80"
    networks:
      - app-network
    depends_on:
      db:
        condition: service_healthy

  db:
    image: postgres:13
    environment:
      POSTGRES_DB: mydb
      POSTGRES_USER: user
      POSTGRES_PASSWORD: password
    networks:
      - app-network
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U user -d mydb"]
      interval: 10s
      timeout: 5s
      retries: 5

networks:
  app-network:
    driver: bridge

volumes:
  postgres_data:
```

**Объяснение:**
- `healthcheck` проверяет готовность PostgreSQL через `pg_isready`
- `app-network` изолирует сервисы
- `postgres_data` volume сохраняет данные
- `depends_on` с `condition: service_healthy` гарантирует запуск web только после готовности db
